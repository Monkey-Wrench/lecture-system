VIMA EXECUTIVE OS — PROJECT CONTEXT FOR GITHUB COPILOT AGENT
===============================================================

PURPOSE
-------
This file captures the current ChatGPT planning conversation for use by
GitHub Copilot running as an agent in Visual Studio Code.

The goal is to build an Executive Director Operating System for VIMA
(Virgin Islands Museum of Art) using Obsidian, local automation, Markdown,
PowerShell, Whisper/whisper.cpp, Ollama, and hot-folder workflows.

IMPORTANT:
- This is a PROJECT CONTEXT / REQUIREMENTS document, not executable code.
- Do not assume that every implementation detail has already been decided.
- Preserve the existing lecture/audio pipeline where practical.
- Build incrementally and explain changes clearly.
- The user has limited technical experience beyond being an experienced
  end user and needs exact, step-by-step implementation instructions.
- The user is working on a Mac but the existing lecture automation uses a
  remote Windows 11 Pro machine with PowerShell/Task Scheduler. Determine
  the appropriate execution environment before changing that architecture.


===============================================================
1. CORE CONCEPT
===============================================================

The VIMA system should be an Executive Director Operating System in
Obsidian.

The academic system and lecture system were the conceptual starting point,
but the VIMA system must be organized around:

- decisions
- institutional knowledge
- relationships
- programs
- governance
- projects
- execution
- strategic priorities
- meetings
- documents
- research
- follow-up
- commitments
- risks
- opportunities

The core workflow is:

    CAPTURE
       |
       v
    AUTOMATED PROCESSING
       |
       v
    STRUCTURE / INTERPRETATION
       |
       v
    MARKDOWN
       |
       v
    OBSIDIAN
       |
       v
    REVIEW
       |
       v
    ACTION / EXECUTIVE INTELLIGENCE

Two primary automated intake pipelines are required:

1. Audio -> transcription -> executive Markdown
2. PDF -> text extraction -> executive summary Markdown

A third manual path should exist:

3. Quick capture -> Inbox -> processing/review

21. DESIGN PRINCIPLES
===============================================================

1. LOW FRICTION
   Capturing information should be extremely easy.

2. AUTOMATE REPETITIVE WORK
   File processing, transcription, extraction, classification, and
   initial structuring should be automated.

3. HUMAN REVIEW
   AI-generated material should pass through an Inbox before becoming
   permanent institutional knowledge.

4. EXECUTIVE ORIENTATION
   The system should prioritize decisions, actions, risks, opportunities,
   relationships, and strategic relevance.

5. INSTITUTIONAL MEMORY
   The system should preserve context and history over years.

6. LINK INFORMATION
   Meetings, people, projects, programs, decisions, and documents should
   connect to one another.

7. LOCAL-FIRST WHERE PRACTICAL
   The existing Ollama/Whisper approach is preferred when technically
   practical, particularly for institutional information.

8. DO NOT OVERENGINEER
   Build a working system incrementally rather than attempting a giant
   automation framework at once.

9. EXPLAINABLE
   The user should understand what each component does and how to
   troubleshoot it.

10. PRESERVE EXISTING WORK
    Do not break the academic lecture system while building VIMA.
